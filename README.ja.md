<h1 align="center">Meido</h1>

<p align="center"><strong>単一スレッドのチャットボットを超えた、パーソナルエージェント OS。</strong></p>

<p align="center">
  <a href="README.md">English</a> ·
  <a href="README.zh-CN.md">简体中文</a> ·
  <a href="README.ja.md">日本語</a>
</p>

Meido は、パーソナルエージェントに継続性を与えます。今何が重要か、以前何が起きたか、
ナレッジベースに何があるか、次の行動をどの運用手順に従って実行すべきかを、一つの
コンテキストとして扱います。個別の一問一答ではなく、多次元コンテキスト管理、継続的な
実行環境、そして利用者が管理できるランタイムを統合します。

単一の Rust ランタイムが、**40 以上のモジュール式スキル**、**35 以上の MCP ツール**、
スケジュールジョブ、Web とチャット上の複数エージェントエンジンを統括します。すべての
チャネルが同じエージェント実行経路を使うため、メモリ、権限、安全ポリシー、追跡可能性が
一貫して保たれます。

## Meido を選ぶ理由

多くのアシスタントの記憶はチャット画面の端で途切れます。Meido は作業用コンテキストを
システムとして管理します。

- **3 層セッションメモリ** — 永続的なアイデンティティと原則、進行中のプロジェクト、
  直近のフォーカスを分離し、短期的なノイズが長期記憶を上書きするのを防ぎます。
- **MemPalace リコール** — アーカイブ全体を毎回プロンプトに詰め込まず、関連知識を
  セマンティック検索で呼び戻します。
- **Bulletin フォーカス** — 各 Persona が「今重要なこと」を短く可視化して保持します。
- **Obsidian ナレッジ Vault** — 人が読めて、持ち運べて、直接編集できる Markdown を
  維持しながら、検索・索引作成・更新を行えます。
- **追跡可能なエージェント履歴** — 追記専用のメモリイベントと実行成果物により、
  エージェントの挙動をブラックボックスにしません。

## 一つのランタイム、複数のインターフェース

- **共通エージェント経路** — Web、Telegram、Discord、WhatsApp、WeCom、スケジュール
  ジョブは、すべて同じオーケストレーション入口を利用します。
- **複数のエージェントエンジン** — Persona ごとに Classic、Cursor、Gemini ADK を
  選択しながら、共通のコンテキストと制御を維持できます。
- **モジュール式の能力レイヤー** — 必要な時だけスキルを有効化し、ワークフローごとに
  別のボットを作らず MCP サーバーを接続できます。
- **スケジュール・バックグラウンド実行** — 定期ジョブや長時間タスクでも、ライブ会話と
  同じ Persona、メモリ、ツール、配信経路を使います。
- **Web オペレーターコックピット** — Persona、モデル、チャネル、フック、スキル、
  スケジュール、メモリ、システム状態を一か所で管理できます。

## 安全性も OS の一部

Meido は安全性をプロンプト末尾の注意書きだけで済ませません。Vault の SOP を
エージェントコンテキストへ組み込み、ツール権限をサーバー側で検証し、シークレットを
マスク・秘匿化します。パスは Persona ごとに制限され、重要な作業はエージェント履歴と
成果物から確認できます。

## 主な機能

- ファイル、シェル、ブラウザー、リポジトリ対応編集を含むローカルワークスペース操作
- Obsidian Vault 検索、セマンティックリコール、自動索引、Markdown ネイティブな知識管理
- Persona ごとのメモリ、モデル、フック、スキル、権限、外部パス設定
- 複数 Persona の共同作業、ゲストターン、共有ボード、バックグラウンド引き継ぎ
- Anthropic、OpenAI、Gemini、ローカルモデル、その他の設定済みコネクター
- Web、Telegram、Discord、WhatsApp、WeCom への配信
- Cron 形式のスケジュール、バックグラウンドジョブ、状態追跡、結果配信
- SOP による安全ガードレールを備えた拡張可能なスキルと MCP ツール

## クイックスタート

### 1. インストール

Linux / macOS：

```bash
curl -fsSL https://raw.githubusercontent.com/kenpyfin/meido/main/install.sh | bash
```

Windows では [`install.ps1`](install.ps1) を使用します。ソースからビルドする場合：

```bash
cargo build --release
cd web && npm ci && npm run build
```

### 2. `.env` の準備

Meido は現在のディレクトリにある `.env` を読み込みます。`MEIDO_CONFIG` で別のパスも
指定できます。

```bash
cp .env.example .env
```

最初はワークスペースと Web 起動用の値だけを設定します。LLM、Vault、MemPalace、
Steel Browser、チャネル、Persona は Web セットアップウィザードから設定できます。
`.env` はコミットしないでください。

### 3. 起動

```bash
meido start
```

**http://127.0.0.1:10961** を開きます。`meido start` はバックグラウンドで動作し、
`meido stop` で停止します。端末に接続したまま実行するには `--foreground` を付けます。

Web UI だけでも利用できます。Telegram、Discord、WhatsApp、WeCom はすべて任意です。
少なくとも一つのクラウドモデル用 API キーを設定するか、キー不要のローカルモデルを
選択してください。

### 4. 任意のログインサービス

macOS と Linux ではユーザーサービスとして登録できます。

```bash
meido gateway install
meido gateway status
meido gateway logs
```

## メモリモデル

チャットと Persona ごとの正規メモリは、次の場所に保存されます。

- `groups/{chat_id}/{persona_id}/memory_state.json` — 現在の 3 層メモリ状態
- `groups/{chat_id}/{persona_id}/memory_events.jsonl` — 追記専用の監査・復旧イベント

`memory_state.json` には、アイデンティティ、長期記憶、進行中のプロジェクト、直近の
フォーカス、作業パターンの記憶、MemPalace 参照が含まれます。書き込み前に正規化と検証を
行い、一時ファイル、アトミックなリネーム、バックアップでデータを保護します。

すべての設定項目は [`.env.example`](.env.example) を、詳しいフィールド仕様と運用情報は
[英語版 README](README.md) を参照してください。
