一つの会話を、多次元のコンテキストが生かします。3 層のメモリ、MemPalace のリコール、
Service briefing、そして Obsidian の Vault です。一つの Rust ランタイムが、その会話を
Web と各チャット、スケジュールジョブへ運び、SOP のガードレールと追跡できる履歴を伴います。

## 新しいチャットを開くのは、やめる

クラウドのチャットボットは、終わったセッションの積み重ねです。ウィンドウがいっぱいになると
スレッドは切れ、次のメッセージはゼロから始まります。進行中だった作業は前の窓に残り、
新しいチャットで説明し直すことになります。

Meido にセッションの境目はありません。毎ターン、コンテキストが整えられるので、同じ会話が続きます。
続けるために、新しいスレッドを開く必要はありません。

## 会話が途切れない理由

**一つのスレッド。** Web、Telegram、Discord、WhatsApp、WeCom、そしてスケジュールジョブは、
同じ会話に入ります。再開するための「新しいセッション」はなく、チャネルごとに別の頭脳が育つこともありません。

**層になったコンテキスト。** 長く残る事実、進行中の作業、直近のフォーカスは分けて置かれます。
長いチャットが最後の数言に潰れたり、直近の細部が、作業がまだ依存している内容を上書きしたりしません。

**必要なときだけ呼び戻す。** MemPalace と Obsidian の Vault は、このターンに要るものだけを戻します。
書庫をプロンプトへ貼り付けず、終わったセッションの中へ置き去りのままにしません。

**フォーカスは作業とともに動く。** Service briefing とトピックの一覧が、今この会話が何をしているかを示します。
それより前のターンは、履歴の中に残ります。

## 新しいチャットか、同じチャットか

**ターンはどこから始まるか**

- よくあるクラウドのチャットボットはセッションを開きます。戻ってきたときは、また一つ開きます。
- Meido は、すでに続いている会話を続けます。

**ウィンドウがいっぱいになったとき**

- よくあるクラウドのチャットボットはスレッドを終えます。次のプロンプトに過去はありません。
- Meido は履歴を予算に合わせて切り詰め、残りのコンテキストを保ちます。層、リコール、Service briefing、Vault です。

**コンテキストはどこにあるか**

- よくあるクラウドのチャットボットは、そのセッションの中、他者のサービス上に置きます。
- Meido はあなたのマシンに置きます。Persona のメモリ、MemPalace、そして読める Markdown の Vault です。

**どこから話せるか**

- よくあるクラウドのチャットボットは、一つの窓です。
- Meido は同じ会話です。Web、Telegram、Discord、WhatsApp、WeCom に現れます。

**窓の外でも続く作業**

- よくあるクラウドのチャットボットは、あなたが再び開くまで待ちます。
- スケジュールとバックグラウンドの作業は、同じ会話へ戻ります。同じ Persona と、同じツールです。

**あとから確かめられるもの**

- よくあるクラウドのチャットボットが残すのは、閉じたセッションの記録です。
- Meido が残すのは、エージェント履歴、追記専用のメモリイベント、その実行に結ばれた成果物です。
  ツールはサーバー側で認可され、シークレットはマスクされ、Vault の SOP はコンテキストに残ります。

## チャットを続ける

バイナリを入れ、Meido を起動し、Web 画面でセットアップを終えます。[クイックスタート](#クイックスタート)。

## Meido の考え方

ターンは組み立てます。まとめて流し込みません。アイデンティティ、原則、層になったメモリ、
有効にしたスキル、Vault の運用手順、そして今のタスクが、そのターンのコンテキストになります。
古い履歴は予算に合わせて切り詰めます。画像には上限があります。記録は一つの会話のままです。

どの入口も同じ経路です。Web UI、Telegram、Discord、WhatsApp、WeCom、スケジューラは、
それぞれチャットを解決してから、一つのランタイムへ渡します。チャネルが独自のエージェントを持つことはありません。

エンジンは選べます。コンテキストは分かれません。各 Persona は、組み込みのツールループである Classic、
Cursor、Gemini ADK のいずれかを実行できます。メモリ、権限、フック、配信は、その選択の外側に残ります。

チャット用のモデルは、バックグラウンド用のモデルではありません。システム LLM が、トピックの題名や
Service briefing のような静かな作業を担います。その組が無いときは、その作業を飛ばします。Persona のチャットモデルを
黙って借りることはありません。

作業には手順があります。Vault の SOP はコンテキストの一部です。ツールはサーバー側で認可されます。
シークレットはマスクされます。パスは Persona ごとに制限されます。ターンが終わったあと、履歴と成果物を確認できます。

## ふだん使うもの

### 操作デスク

Web のコックピットが、Meido を動かす場所です。ワークスペース、Vault、モデル、システム LLM、
MemPalace、管理ブラウザーが揃うまで、セットアップウィザードが開きます。残りは設定と Persona のページで編集します。
作業ディレクトリの `.env` が起動用の設定です。ワークスペース、待受アドレス、Vault のパスを変えたときは再起動が要ります。
API キーとランタイムの切り替えは、保存した時点で効きます。macOS と Linux では、任意のログインサービスが
ログイン時に Meido を起動します。

### Persona

Persona には、名前、エンジン、モデル、自分のメモリ、Service briefing、フック、スキル、外部パスがあります。
複数の Persona が一つのチャットを共有できます。それぞれが、自分のコンテキストで答えます。

### 続くチャット

デスクが、その会話です。サイドバーには Persona、グループ、ボードがあります。開いている Persona は
一つの記録を保ちます。横のトピック一覧は、同じ記録の区切りに題を付け、題の絞り込みは新しいセッションを開きません。
スレッドの上にある Service briefing が、このチャットが今していることを示します。Focus と Transcript は、その二つの見方です。
Hide scheduled は、定期実行を視界から外します。削除はしません。Side chats はこのスレッドに付いたままです。
ブックマークは、その中のメッセージへ戻ります。

### 会話を続けるコンテキスト

3 つの層が、長く残る事実、進行中の作業、直近のフォーカスを持ちます。MemPalace が関連することを呼び戻します。
Service briefing は、スレッドの上で今のフォーカスを示します。Obsidian の Vault は、読めて、検索でき、索引を作れる Markdown です。
Persona メモリの項目ごとの仕様は、[英語版 README のメモリ仕様](README.md#memory-file-spec)を参照してください。

### 共同作業

`@Name` と書くと、別の Persona を招けます。ゲストは、タグした順に、自分自身として、ホストの記録へ答えます。
グループは別の会話で、自分の記録を持ちます。ボードは四つの段階です。TODO、PLAN、BUILD、VERIFY。
どのカードにも Deploy と Complete があります。列の上にある Today は、カード、実行、これから始まる作業のライブ概要です。

### 続きの作業

定期ジョブとバックグラウンドジョブは、ライブのターンと同じ Persona とツールを使います。長いシェルコマンドは
バックグラウンドで実行できます。終わった実行は、チャットへ添付して戻せます。実行から公開されたファイルは、
その実行に結ばれた成果物になります。返信へ置いただけのパスにはなりません。

### エンジンとモデル

Classic は組み込みのツールループです。Cursor と Gemini ADK は、Persona ごとに選ぶ別のエンジンです。
Anthropic、OpenAI、Gemini、その他の設定済みプロバイダへ接続するか、ローカルサーバー
（`ollama`、`llama`、`llamacpp`）を Persona に向けます。クラウドのモデルが要らない作業は、ローカルの経路に残せます。

### 自分で加えるもの

スキルと MCP サーバーは、このマシンへ自分で入れます。Meido は、その Persona に許されたスキルを有効にし、
設定した MCP サーバーへ接続します。受け入れなければならない固定の一覧はありません。

### フック

確認はターンの周りで走ります。始まる前、ツール使用の前後、返信を届ける前、届けたあとです。
組み込みの確認は、フォーカスの同期、スケジューラの方針、スキルの制限、止まったツールループの遮断、
チャットへそのまま置けない密な返信の扱い、シークレットの除去を行います。自分の確認も追加できます。

### 触れるマシン

Meido はあなたのワークスペースで働きます。ファイル、シェル、リポジトリを踏まえた編集です。
API だけでなくページが要るときは、セットアップウィザードから管理ブラウザー Steel を入れられます。
新しいワークスペースには、[`defaults/AGENTS.md`](defaults/AGENTS.md) から運用原則が渡されます。
すでに原則ファイルがある場合は、そのまま残します。

### チャネル

Web UI だけで足ります。Telegram、Discord、WhatsApp、WeCom は、同じチャットへ届く任意の経路です。

### 安全性と追跡

ツールの使用はサーバー側で認可されます。各 Persona には自分のパス範囲があります。シークレットはマスクされ、
出力は秘匿化されます。Vault の SOP はコンテキストに残ります。メモリの変更はイベントログへ追記されます。
エージェント履歴は、そのターンが実際にどう走ったかを残します。

## クイックスタート

### 1. インストール

Linux / macOS：

```bash
curl -fsSL https://raw.githubusercontent.com/kenpyfin/meido/main/install.sh | bash
```

Windows では [`install.ps1`](install.ps1) を使用します。ソースからビルドする場合：

```bash
cargo build --release
cd web && npm ci && npm run build
```

### 2. `.env` の準備

Meido は現在のディレクトリにある `.env` を読み込みます。`MEIDO_CONFIG` で別のパスも
指定できます。

```bash
cp .env.example .env
```

最初はワークスペースと Web 起動用の値だけを設定します。LLM、Vault、MemPalace、
Steel Browser、チャネル、Persona は Web セットアップウィザードから設定できます。
`.env` はコミットしないでください。

### 3. 起動

```bash
meido start
```

**http://127.0.0.1:10961** を開きます。`meido start` はバックグラウンドで動作し、
`meido stop` で停止します。端末に接続したまま実行するには `--foreground` を付けます。

Web UI だけでも利用できます。Telegram、Discord、WhatsApp、WeCom はすべて任意です。
少なくとも一つのクラウドモデル用 API キーを設定するか、キー不要のローカルモデルを
選択してください。

### 4. 任意のログインサービス

macOS と Linux ではユーザーサービスとして登録できます。

```bash
meido gateway install
meido gateway status
meido gateway logs
```

## メモリモデル

チャットと Persona ごとの正規メモリは、次の場所に保存されます。

- `groups/{chat_id}/{persona_id}/memory_state.json` — 現在の 3 層メモリ状態
- `groups/{chat_id}/{persona_id}/memory_events.jsonl` — 追記専用の監査・復旧イベント

`memory_state.json` には、アイデンティティ、長期記憶、進行中のプロジェクト、直近の
フォーカス、作業パターンの記憶、MemPalace 参照が含まれます。書き込み前に正規化と検証を
行い、一時ファイル、アトミックなリネーム、バックアップでデータを保護します。

すべての設定項目は [`.env.example`](.env.example) を、詳しいフィールド仕様と運用情報は
[英語版 README](README.md) を参照してください。
